# Security Policy 🔐

## Reporting a vulnerability

If you find a security problem in this repo — a stale IP that now belongs to a real host, a link to something dead or dangerous, a screenshot containing something sensitive, or any content that reads more like an attack guide than a write-up — please report it.

**Email:** `security@merry-clickmas.example` (placeholder — this is a parody repo, not a company)
**Or:** open a private report / a regular issue, whichever your platform offers. If in doubt, open an issue that says "I need to report something privately" and nothing else.

Please don't publicly disclose a hosting problem (like a screenshot revealing a live endpoint) before it's fixed.

## What we consider in scope

| In scope | Out of scope |
|---|---|
| Live credentials, keys, or tokens accidentally committed | The room's fictional password — it's a lab artefact and meant to be public |
| Screenshots exposing real hosts or people | AttackBox/target IPs from the screenshots; these were transient lab addresses |
| Content that could be used to attack a real person or org | Jokes. The jokes are in scope only if they're bad. Many are. |
| Instructions that, if followed, would harm someone | Your displeasure at the elf characters |

## Our promises

1. **Blame-free.** You will not be scolded for reporting. Reporting is the whole point of the write-up this repo is based on.
2. **Fast response.** A human (not an elf, not an LLM, not a reindeer) will look at it.
3. **Credit if you want it.** Or stay anonymous. Both are correct answers.

## How to report a *real* phish (not a repo issue)

This repo is about a lab, but real inboxes are full of the real thing. If you get one:

1. **Don't click, don't reply, don't forward casually.**
2. Use your organisation's official report button or security channel.
3. If you already clicked: report immediately. Speed beats embarrassment, every single time.
4. If you entered credentials: change that password, change it anywhere else it was reused, and ask your security team to review sign-in activity and mailbox rules.

## A note on this repo's spirit

The entire lesson of the room this repo documents is that humans click, and that the fix is a system where clicking is survivable — MFA, uniqueness, and a reporting route that doesn't come with a penalty. This policy is written in that spirit: **you will never be in trouble here for saying something's wrong.**
